## Задача в очереди: замена 3D-иконок на лендинге — готово на диске, требует git/PR

Daria прислала 3 новых 3D-иконки (сгенерированы через инструмент «Claude Design», заменяют старые: Time/sparks, Legal liability/stack, Tooling/gears). Файлы `.webm` Daria уже положила сама, напрямую на диск, по путям:

(подтверждено сверкой mtime/размера и прямым ffprobe/извлечением кадров — реально новый контент, не старые файлы).

Сайт использует **luma-matte** приём для Safari (WebM VP9 alpha не поддерживается нативно в H.264/Safari): `landing/landing.js`, функция `createAlphaCanvasIcon` (~строка 247), берёт `.webm`-путь, отрезает расширение и составляет из него имена двух H.264-файлов — `{base}-rgb.mp4` (цвет) и `{base}-alpha.mp4` (grayscale, яркость = альфа-канал), которые композитит через `<canvas>`/`getImageData`/`putImageData` в рантайме. В `index.html` и `landing.js` явных путей к `-rgb.mp4`/`-alpha.mp4` нет — они выводятся только из имени `.webm` в JS.

**Сделано в этой сессии (Cowork, без git-доступа) — уже на диске Daria:**

Пересобраны все 6 файлов Safari-фолбэка (`-rgb.mp4` + `-alpha.mp4` для каждой из 3 иконок) под новый контент `.webm`, тем же методом, что задокументирован в `HANDOFF_COWORK_2026-08-10.md`/`-11.md`, с двумя доработками относительно прошлого рецепта:

1. **Явный VP9-декодер обязателен**: `-c:v libvpx-vp9` нужно указывать **до** `-i` — иначе ffmpeg по умолчанию выбирает декодер, который тихо не отдаёт alpha side-channel VP9 (получается alpha, залипшая на 255/непрозрачно, несмотря на корректные метаданные `alpha_mode=1` в самом файле). Без этого фикса alpha-видео на выходе оказывается пустым/непрозрачным без какой-либо ошибки в консоли.
2. **Чётные размеры обязательны для libx264**: если ширина/высота исходника нечётные (было 249×418), добавить в filter chain `scale=trunc(iw/2)*2:trunc(ih/2)*2` — иначе `libx264` падает с `width not divisible by 2`.
3. **Качество кодирования**: `-crf 14 -preset slow` для обоих проходов (rgb и alpha) — на `-crf 18` появлялись видимые тёмные ободки/ореолы по краям при композитинге (особенно заметно на tooling/шестерёнках). RGB-проход кодируется прямой конвертацией `format=yuv420p` без композитинга на чёрный фон — композит на чёрном перед кодированием создавал шов на полупрозрачных краях.

Пример рабочей команды (повторить для каждой из 3 иконок, `sparks`/`stack`/`tooling`):

```bash
# RGB-проход
ffmpeg -c:v libvpx-vp9 -i meginn-icon-<name>.webm \
  -vf "scale=trunc(iw/2)*2:trunc(ih/2)*2,format=yuv420p" \
  -c:v libx264 -crf 14 -preset slow -an \
  meginn-icon-<name>-rgb.mp4

# Alpha-проход (grayscale, яркость = альфа)
ffmpeg -c:v libvpx-vp9 -i meginn-icon-<name>.webm \
  -vf "alphaextract,scale=trunc(iw/2)*2:trunc(ih/2)*2,format=yuv420p" \
  -c:v libx264 -crf 14 -preset slow -an \
  meginn-icon-<name>-alpha.mp4
```

Верификация: композит на ярко-зелёном тестовом фоне (стресс-тест краёв) + композит на реальном тёмном фоне продакшена — оба чистые, без ореолов, для всех трёх иконок. Файлы записаны обратно на диск Daria через device-bridge (`force: true`, т.к. mtime не менялся с последнего стейджинга).

## Добавление (Claude Code, та же дата) — задача выполнена и смержена, плюс новый баг найден и починен по дороге

Все 9 шагов выше выполнены по плану: ветка `preview/meginn-3d-icons-refresh`, PR #7 (в `PROD300/MEGINN-monorepo`, репозиторий уже переименован), точечный коммит только 9 файлов иконок, Vercel preview получен и отдан Daria на проверку в Safari.

**Найден новый баг при проверке на Safari, не упомянутый выше**: при рестарте луп-видео на карточках виден кратковременный чёрный фон за фигурами (не халка по краям — это уже было починено в этой же сессии Cowork, — а именно вспышка на границе цикла). Причина: `createAlphaCanvasIcon()` в `landing.js` держит `rgbVideo` и `alphaVideo` как два независимых `<video loop>` элемента — нативный `loop` не гарантирует, что оба перезапустятся на одном и том же кадре. Когда они расходятся, альфа-маска на миг перестаёт совпадать с формой в цветном видео, и незаматованный тёмный фон rgb-исходника проступает как будто непрозрачный.

Чинили в 3 итерации (все в PR #7, финальная версия — то, что сейчас в `main`):
1. Первая попытка — сверять `currentTime` обоих видео на каждом кадре `draw()` и пересикать `alphaVideo` при расхождении >50мс. **Стало хуже**: обычный джиттер между двумя независимо декодирующими видео сам регулярно пересекает такой порог, получился постоянный пересик = постоянные заикания, а не разовая коррекция на границе цикла. Особенно плохо на Sparks/Stack.
2. Убрали нативный `loop` у обоих видео полностью. Вместо этого — слушатель `ended` только на `rgbVideo` («ведущее» видео): по этому событию оба видео синхронно сбрасываются на `currentTime = 0` и запускаются заново в одном обработчике. Один синхронный момент синхронизации на цикл вместо непрерывной коррекции. Починило Tooling и Stack, но **Sparks остался с рассинхроном**.
3. Причина, почему Sparks не чинился: даже у файлов с одинаковым числом кадров/длительностью (проверено `ffprobe -count_frames` — точное совпадение по всем трём парам) декодирование в реальном времени может идти с разной скоростью в зависимости от сложности контента. У Sparks (быстрые частицы) декодирование, судя по всему, дороже/менее предсказуемо, чем у Stack/Tooling (более медленные плавные формы) — то одно, то другое видео из пары может реально доиграть до конца раньше другого и застыть на последнем кадре, ожидая, пока досмотрится более медленное. **Финальный фикс**: слушатель `ended` повешен на оба видео — какое первым закончилось, то и триггерит совместный рестарт обоих, независимо от того, в какую сторону идёт рассинхрон. С небольшим guard-флагом на случай, если оба `ended` срабатывают в один тик (для контента с равной скоростью декодирования).

Подтверждено Daria на живом Safari-превью после третьей итерации — «отлично» — и смержено в `main` (fast-forward, коммит `589bf72`).

**Для следующего агента**: если ещё какая-то из будущих 3D-иконок (тот же luma-matte приём) покажет похожий рассинхрон/чёрную вспышку на рестарте цикла — это тот же паттерн, решение уже есть в `createAlphaCanvasIcon()`, отдельно решать не нужно, оно общее для всех иконок через эту функцию.
