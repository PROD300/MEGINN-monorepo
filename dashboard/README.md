# Дашборд юзер-тестов — бандл

Готовый дашборд аналитики поведения для прототипа. Курс отдаёт его архивом: студент распаковывает в корень своего проекта и запускает директиву `directive_dashboard` — она встраивает трекер в прототип, поднимает сбор на сервере и подключает дашборд к данным проекта. Дальше: пуш → живая версия шлёт события → дашборд читает их с живой версии.

## Что внутри

```
dashboard/
  tracker/track.js        — трекер: вставляется в прототип, шлёт события (клики + флаг интерактивности, переходы, сессии, время, метка сценария из ?ut_task=)
  server/server.js        — сбор + анализ (Node, без зависимостей): /collect, /stats, /rounds, /hypotheses, /baseline, /health
  server/package.json     — запуск: node server.js
  app/index.html          — дашборд (самодостаточный, без сборки)
  app/config.example.js   — образец конфига; рабочий config.js генерит директива (адрес сбора, prototypeUrl, сценарии flows[], имена экранов, ключ)
  hypotheses.example.json — формат гипотез проекта (дашборд их читает и приоритизирует)
```

Ученик **ничего не вводит руками**: директива поднимает сбор, узнаёт адрес и параметры сценария проекта и пишет их в `app/config.js`. Дашборд читает этот конфиг и открывается уже подключённым.

## Что показывает дашборд

- **Сигналы трения из чистых событий** (без записи экрана и пикселей): rage-клики, dead-клики (ложные аффордансы), быстрый возврат/pogo, метание, заминки → **friction score 0–100 по экранам**.
- **Воронка с контекстом**: где отвал + что кликали перед выходом + разбивка по устройству.
- **Метрики качества**: task success, lostness (Smith 1996), first-click success — с доверительным интервалом (Adjusted-Wald) и флагом достоверности при малом n.
- **Сегменты** по устройству с авто-флагом разрыва (мобайл vs десктоп).
- **Сессии как мини-replay**: путь с маркерами трения по шагам.
- **Авто-находки** (severity-anchored RICE) и **бриф агенту** (Markdown/JSON) с доказательством, гипотезой правки и критерием успеха.
- **Цикл «было → стало»**: фиксируешь базу, после правок агента видишь дельты.

## Как работает (коротко)

1. **Трекер** пишет события по экранам/элементам (не пиксельно) и батчами шлёт на сбор.
2. **Сбор+анализ** на твоём сервере копит `events.jsonl` и считает все метрики/сигналы/находки из событий. Без внешней БД и зависимостей.
3. **Дашборд** читает агрегаты и показывает картину выше. Подключение делает директива — руками ничего не правишь (`directive_dashboard`).

## Честность к малой выборке

Тестеров обычно 5–10. n=5 надёжно ловит частые проблемы (≈91% самых частых), но не длинный хвост (≈38% всех). Поэтому дашборд показывает counts + доверительный интервал, помечает «1 из N» низкой достоверностью и подаёт метрики как **флаги проблем, а не доказательство, что дизайн хорош** (NN/g, MeasuringU).

## Данные и приватность

Трекер собирает только поведение в прототипе (какие экраны, какие клики, длительность) — без ввода пользователей и персональных данных, без записи экрана. Хранилище (`events.jsonl`) живёт на твоём сервере, не уходит наружу.
