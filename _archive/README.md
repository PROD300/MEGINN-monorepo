# Архив

Перенесено сюда при сборке AI-среды (`/release-environment`, 2026-06-22). Ничего не удалено — для откатов и сверки.

## `directives/` (32 файла)

Бывшая `agents/directives/`. Директивы как жанр заменены навыками в `.claude/skills/` — почти все 1:1, см. таблицу соответствия в `.claude/skills/release-environment/SKILL.md`. Несколько файлов не стали навыками:

- **`directive_briefing_first_tien.md`** — более ранняя простая версия рекурсивного брифинга. Заменена навыком `/briefing`, который собран на основе более полной `directive_agent_briefing.md`.
- **`connect_notion_mcp.md`** — разовая инструкция подключения Notion MCP, уже выполнена однократно при первом подключении. Если понадобится переподключить на новой машине — инструкция здесь, как справка.
- **`routing_rules.md`** — правила маршрутизации между `@product-brief-architect` и `@ux-capital-flow-architect` (легаси-агентами, см. ниже). Логика маршрутизации (бизнес-трек vs UX-трек) перенесена в `CLAUDE.md` → раздел «Как работать с проектом».
- **`prompt_renovative_metrics.md`, `prompt_asset_system_v2.md`, `prompt_smart-contract_architect.md`** — это не процедуры, а одноразовые архитектурные правки (миграция системы метрик на Tier-1, пересборка системы активов, институциональная ревизия смарт-контрактов), уже применённые к проекту в `prd.md`/`brief.md`. Не навыки — исторический контекст решений.

## `agents/` (3 файла)

Легаси-спека мульти-агентной архитектуры из другого инструмента (frontmatter `mode: subagent`, `temperature` — не формат Claude Code; привязка к несуществующему `bigPickle.md`):

- `agent_obsidian_product_architect.md` — оркестратор-персона.
- `product-brief-architect.md` — продуктовый субагент.
- `ux-capital-flow-architect.md` — UX-субагент.

Их работу теперь покрывают навыки (`/briefing` и др.) и маршрутизация в `CLAUDE.md`. Решено не переносить их 1:1 в `.claude/agents/`: оба описывают многораундовый интерактив с пользователем и синтез текста, зависящий от контекста разговора — а субагенты Claude Code не видят историю диалога и не имеют доступа к `AskUserQuestion`, так что для этой работы подходит не субагент, а навык, выполняемый основным агентом.
