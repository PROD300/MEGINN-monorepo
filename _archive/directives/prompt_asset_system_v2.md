# TASK: Полная переработка системы типов активов OBSIDIAN (Asset System v2 — Institutional Grade)

## Контекст

Текущая система типов активов OBSIDIAN:

* перегружена (избыточные токены и NFT)
* ориентирована на DeFi-паттерны
* не соответствует требованиям институциональных клиентов
* не поддерживает Tier-1 метрики (AUM, контроль, проверяемость)

Необходимо перейти к:

> **минималистичной, контролируемой и соответствующей требованиям системе активов**

---

## Каноническая модель (Asset System v2)

Используй ТОЛЬКО эту модель как источник истины:

---

### 🔷 Core Asset Layer

| Тип                       | Стандарт            | Описание                                         | Приоритет |
| ------------------------- | ------------------- | ------------------------------------------------ | --------- |
| Base Assets               | ERC-20              | ETH, USDC, wBTC — базовые ликвидные активы       | M         |
| Vault Shares              | ERC-4626            | Доли в стратегиях / хранилищах                   | M         |
| Permissioned Assets (RWA) | ERC-1400 / ERC-3643 | Токенизированные реальные активы с ограничениями | M         |

---

### 🔷 Ownership & Position Layer

| Тип            | Стандарт                | Описание                                                  | Приоритет |
| -------------- | ----------------------- | --------------------------------------------------------- | --------- |
| Position Token | ERC-721 / account-based | Представление позиции пользователя (портфель / стратегия) | M         |

---

### 🔷 Control & Identity Layer

| Тип                    | Стандарт              | Описание                                  | Приоритет |
| ---------------------- | --------------------- | ----------------------------------------- | --------- |
| Smart Accounts         | Account abstraction   | Управляемые кошельки с ролями и правилами | M         |
| Identity-linked Assets | ERC-3643 (расширение) | Привязка активов к whitelist / KYC        | M         |

---

### 🔷 Protocol Token (ограниченно)

| Тип            | Стандарт | Описание                                            | Приоритет |
| -------------- | -------- | --------------------------------------------------- | --------- |
| OBSIDIAN Token | ERC-20   | Утилитарный токен (оплаты, ограниченное управление) | S         |

---

### 🔷 Advanced Layer

| Тип                     | Стандарт          | Описание                               | Приоритет |
| ----------------------- | ----------------- | -------------------------------------- | --------- |
| Structured Products     | ERC-4626 + кастом | Tranches, risk layers                  | S         |
| Strategy Registry       | Smart contracts   | Реестр стратегий (вместо Strategy NFT) | M         |
| Off-chain Linked Assets | Hybrid            | Связка с оффчейн данными               | M         |

## 3. Связка с Tier-1 метриками (обязательно)

Для каждого типа актива явно указать:

  * Volume
  * Client Acquisition
  * Control (Approvals)

  * Security

Если связь не очевидна → актив должен быть удалён или переработан.
