Daria поменяла порядок передачи изменений второму агенту. **Старое правило («коммитить и пушить после каждой выполненной команды», см. ниже в этом же файле) отменено этим обновлением.**

Новая схема (по аналогии с тем, как уже работаем по `app/` — WebApp):

1. Второй агент **не коммитит и не пушит сразу**.
2. Второй агент **развёртывает изменения на dev-сервере** (`npm run dev` / локальный превью, либо dev-деплой, если так удобнее) и даёт Daria **ссылку/доступ на апрув**.
3. Daria смотрит и **аппрувит** (или просит доправить).
4. **Только после аппрува** второй агент коммитит и пушит в `main`.

Это правило действует **для всех последующих хэндоверов** от этой Cowork-сессии — не только для правок, описанных в этом файле, но и для всех будущих `HANDOFF_COWORK_*.md`. Остальные случаи этого паттерна (карточка-цитата Security & Compliance, hover-бордер активной строки Hero-таблицы, dev-tweaks остаток) были убраны в предыдущих раундах этой же сессии — теперь `border-left` с акцентным цветом не встречается в `landing/` вообще нигде.

## Добавление (та же сессия, ещё позже) — баг: форма Early Access всегда показывала Success

Daria заметила: секция «Early Access · 2026 Q3» всегда открывается сразу в состоянии Success, а не в дефолтной форме. Причина найдена — CSS-баг, не проблема состояния/JS:

`.form__success` (`landing.css`) задаёт `display: flex` на уровне класса без исключения для нативного атрибута `hidden` — авторский CSS всегда перебивает встроенное `[hidden] { display: none }`, поэтому блок был виден постоянно, даже с `hidden` в разметке (`<div class="form__success" id="formSuccess" hidden>` в `index.html` — сама разметка и JS были в порядке, `landing.js` корректно делает `success.hidden = false` только по сабмиту формы).

**Фикс:** добавлено `.form__success[hidden] { display: none; }` сразу после базового правила. Теперь блок скрыт по умолчанию и появляется только после реального сабмита формы, как задумано.
